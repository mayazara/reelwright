# Decisions

Choices made where `PLAN.md` was ambiguous or silent. Newest last.

| Date | Milestone | Decision | Why |
| --- | --- | --- | --- |
| 2026-10-11 | M0 | The repo root is the Cargo workspace root (no extra `reelwright/` folder). | Simplest layout; matches the plan's tree with the root renamed. |
| 2026-10-11 | M0 | The product name and IDs live in `rw_model::app`. | The plan asks for the name to live in one constant; `rw-model` is depended on by everything. |
| 2026-10-11 | M0 | Accent palette: deep teal `#0E7C74` / `#2BB3A6` with amber highlight `#F2A541`; warm-neutral surfaces. Tokens in `rw-ui/src/theme.rs`, checked for WCAG AA contrast by a unit test. | Plan suggests teal or amber; both kept distinct from the reference editor's colours. |
| 2026-10-11 | M0 | egui's default fonts are disabled; Inter Regular/SemiBold are bundled and used for every family, including Monospace, until a mono face is needed. | Default egui fonts include the Ubuntu Font Licence, which is outside the allowed list; the plan specifies Inter for the UI. |
| 2026-10-11 | M0 | `deny.toml` also allows Unicode-3.0, BSL-1.0, CC0-1.0, MIT-0 and OFL-1.1. | All permissive and GPL-compatible; Unicode-3.0 is required by core crates (`unicode-ident`). GPL/AGPL remain denied. |
| 2026-10-11 | M0 | Licence files that ship with an asset (e.g. `Inter-OFL.txt`) get their own row in `assets/ATTRIBUTION.md`; only `ATTRIBUTION.md` and `manifest.json` are exempt. | Keeps the "every file has a row" rule literal and easy to test. |
| 2026-10-11 | M0 | Panels are named Library, Preview, Inspector, Timeline. | Own naming, per the branding rules. |
| 2026-10-11 | M0 | The offline test uses an unprivileged user + network namespace (`scripts/test-offline.sh`, Linux CI). | No root needed; any socket to a non-loopback address fails. |
| 2026-10-11 | M0 | `brand-lint` falls back to `grep` when `rg` is missing, and skips `Cargo.lock`. | Runs on dev machines without ripgrep; lockfile names are upstream crate names, not our branding. |
| 2026-10-11 | M0 | Logs go to `<data-local-dir>/reelwright/logs/reelwright.log`, `RUST_LOG` overrides the level. | Local file only, per the offline rule. |
| 2026-10-11 | M1 | Projects live in `<Videos>/Reelwright/<name>/` (fallback: app data dir). Each project folder holds `project.rwproj`, a `.bak` of the previous save, and a disposable `cache/`. A folder-picker setting arrives with Settings in M10. | Easy for users to find and back up; matches the local-first rule. |
| 2026-10-11 | M1 | "Recent projects" shows every project in the projects folder plus up to 20 recently opened projects stored elsewhere, newest first. Deleting an outside project only forgets it. | Never delete files outside the app's own folder. |
| 2026-10-11 | M1 | Media fingerprint = BLAKE3 of file size + first and last 1 MiB. | Hashing whole multi-GB files on import is too slow; this is enough to recognise a moved file. |
| 2026-10-11 | M1 | Importing a file whose fingerprint is already in the project is skipped with a notice. | Avoids duplicate bin entries from repeated drops. |
| 2026-10-11 | M1 | A whole import batch is one undo step ("Import N files"). | Matches user intent; one drag-drop = one action. |
| 2026-10-11 | M1 | Proxies: MJPEG (intra-frame, LGPL native encoder) in Matroska, 540 lines tall, video only, made when the source is above 1080p or HEVC/AV1. Audio always plays from the source. | Intra-frame proxies scrub instantly; H.264 1080p decodes fast enough without one; proxying every long-GOP file would make every import slow. |
| 2026-10-11 | M1 | Rotation from the display matrix is snapped to 0/90/180/270 and applied to thumbnails; proxies keep the coded orientation and the source's rotation is applied at render time. | One place applies rotation; arbitrary angles are rare in camera files. |
| 2026-10-11 | M1 | Animated GIF/APNG/WebP are their own media kind ("Animated image") and act like silent video; a single-frame GIF is an image. GIFs report alpha because FFmpeg decodes them to BGRA. | Matches how users think of GIFs; transparency must survive. |
| 2026-10-11 | M1 | 21:9 preset is 2520×1080 (exactly 21:9). | 2560×1080 is 64:27, not 21:9. |
| 2026-10-11 | M1 | Changing the canvas preset in M1 only changes the size; items are re-fitted once transforms exist (M3). | Items have no transform until M3. |
| 2026-10-11 | M1 | Autosave: after 2 s idle following a change, at least every 30 s while changes keep coming, when returning home, and on app exit. Writes are atomic (temp file + rename), keeping the previous file as `.bak`; a corrupt project falls back to the backup. | Plan asks for 30 s + on idle; atomic writes protect against crashes mid-save. |
| 2026-10-11 | M1 | Test fixtures are generated by the `ffmpeg` CLI into `target/fixtures/` (gitignored), with encoder fallbacks per platform; CI sets `RW_MIN_FIXTURES` so a thin matrix cannot pass silently. | Plan forbids committing third-party footage; encoders differ by OS. |
| 2026-10-11 | M1 | `deny.toml` allows WTFPL only for `ffmpeg-next` and `ffmpeg-sys-next`. | PLAN.md names this crate and licence; scoping the exception keeps WTFPL out elsewhere. |
| 2026-10-11 | M1 | Grids of cards (media bin, home screen) lay out by column count instead of egui's wrapping layout. | egui can't wrap framed widgets of unknown width; found via rendered screenshots. |
| 2026-10-11 | M2 | Timeline edits are `TimelineOp`s run by one `TimelineEdit` command that snapshots the tracks for undo and replays recorded ids on redo. | One well-tested path for every edit; property tests cover all ops together. Memory per undo step is proportional to the timeline (small); diff-based undo can replace it if projects grow large. |
| 2026-10-11 | M2 | The main track is an explicit `main` flag on one video track, created with every project (older projects gain one on open). Its items are packed back to back in list order. | Clear semantics; never auto-removed. |
| 2026-10-11 | M2 | On free tracks, an item that would overlap moves to a new track directly above instead of overwriting. | No silent data loss; matches "dropping creates a new track". |
| 2026-10-11 | M2 | Trimming is plain by default; Shift+drag ripples on free tracks. The main track always ripples (magnetic). | Simplest mapping of "trim (ripple and plain)". |
| 2026-10-11 | M2 | Grouped items move, trim (same edge) and delete together; splitting a grouped item puts the right-hand pieces in a new shared group. | Keeps linked video/audio linked on both sides of a cut. |
| 2026-10-11 | M2 | Detach audio groups the new audio item with its video and sets `audio_detached` on the video so the sound isn't doubled. | Moves stay in sync; reversible by undo. |
| 2026-10-11 | M2 | Compositing happens in linear light on an `Rgba16Float` canvas; sources are uploaded as sRGB textures and the output is `Rgba8UnormSrgb`. BT.709 is approximated by sRGB transfer for now; exact BT.709 handling comes with colour tools in M3. | Correct blending now; one place to refine later. |
| 2026-10-11 | M2 | Sources are letterboxed (fit inside) the canvas until per-item transforms arrive in M3. | Mainstream default for mismatched aspect. |
| 2026-10-11 | M2 | The playback clock is the number of samples the audio device has consumed. On an audio underrun the clock stalls rather than letting picture and sound drift. With no audio device a real-time null output drives the clock. | Sync is structural, not corrected after the fact. |
| 2026-10-11 | M2 | Preview decodes layers in parallel and opens decoders for clips starting within 1 s. Playback waits (up to 500 ms) for the first frame before starting the audio clock. | Removed 100 ms stalls at simultaneous cuts on three tracks. |
| 2026-10-11 | M2 | `VideoReader`/`AudioReader` are `Send` via `unsafe impl` (FFmpeg contexts have no thread affinity; `&mut self` guarantees exclusive use). | Needed to decode layers on worker threads. |
| 2026-10-11 | M2 | Export renders on its own headless GPU device (falling back to the UI's), reading every frame back; audio is mixed per frame in exact sample spans. Encoder preference: OpenH264, VideoToolbox, NVENC, QSV, AMF, Media Foundation, libx264 (developer builds only), then FFmpeg's built-in MPEG-4 Part 2 as a last resort. | Export never blocks the preview and always produces a file; hardware selection UI is M5. |
| 2026-10-11 | M2 | Timeline thumbnails come from a per-file filmstrip (≤ 240 tiles, ~1 per second, 64 px tall) packed into one PNG with a JSON layout. | Clips show the right picture at each position at any zoom without per-frame decoding. |
| 2026-10-11 | M2 | Waveform peaks: max of the mono mix per 10 ms, stored as bytes (`RWPK` file). | Small, fast to draw at any zoom. |
| 2026-10-11 | M2 | Audio fades are implemented with visual fades in M3. | The product table lists fades under both M2 (audio row) and M3 (look row); one fade model for both. |
| 2026-10-11 | M2 | Track header icons (lock, eye, speaker, magnet, play/pause) are drawn with the painter. | Original iconography with no icon dependency; may be swapped for Lucide SVGs in M10. |
| 2026-10-11 | M2 | Markers: `M` adds at the playhead; drag on the ruler to move; right-click to remove. They are snap targets and edit points for ↑/↓. | `M` isn't in the plan's shortcut table; it's the common convention. |
| 2026-10-11 | M2 | Real-time and drift targets are checked by `soak_multitrack_1080p` (release build, `RW_PERF=1`, `RW_SOAK_SECS=600`), run manually; CI runs a 5 s debug soak that checks clock correctness only. | Timing tests on shared CI runners are flaky. |
| 2026-10-11 | M2 | Audio output asks the default device for 48 kHz stereo `f32`, else uses the device's own format with channel mapping and linear-interpolation resampling in the callback. If no device opens, playback falls back to the silent real-time output. Latency is measured from callback timestamps and folded into the clock continuously. | Preview must play on any machine; export never uses this path. |
| 2026-10-11 | M2 | On WSL, ALSA needs `pcm.!default pulse` (in `~/.asoundrc`) to reach WSLg's PulseAudio server; the app doesn't write that file. | It's user system configuration. |
| 2026-10-11 | M3 | A clip's look is a box on the canvas (centre + size in canvas fractions) plus fit (fit/fill/stretch), rotation, flips, crop, opacity, blend, colour, filter and fades — one `Look` struct, all defaults meaning "no change". Keyframes are deferred to the keyframe editor (post-M10). | Covers every M3 control and the PiP/split layouts with one representation; old projects load unchanged. |
| 2026-10-11 | M3 | Each layer is a full-canvas GPU pass that reads the canvas below, so all ten blend modes work. Opacity mixing happens in linear light; colour grading and blend modes operate on sRGB-encoded values, as consumer editors do. | Correct cross-fades, familiar-looking blends. |
| 2026-10-11 | M3 | Filters are 24 original looks defined as code (`rw-fx/src/grades.rs`) and shipped as 17³ `.cube` files in `assets/luts/` (generated by `make_luts`); a test fails if code and files disagree. Intensity mixes graded and original values. | Plan asks for original `.cube` presets; small grid sizes keep the repo light and are smooth for broad grades. |
| 2026-10-11 | M3 | Colour controls: exposure in stops (±3) in linear light; temperature/tint as white-balance gains; brightness, contrast, highlights, shadows, saturation, vibrance on sRGB values (each ±1). | Simple, predictable controls; exact formulas live in `rw-render/src/shader.wgsl`. |
| 2026-10-11 | M3 | Fades are per clip and apply to picture (opacity) and sound (gain ramp) together. Splitting keeps the fade-in on the left piece and the fade-out on the right; trims shrink fades to fit. | The plan's "Fade in/out (video and audio)". |
| 2026-10-11 | M3 | Colour/gradient backgrounds are a generated clip kind (no media file), freely resizable like stills; 12 colours and 8 gradients are original presets; the colour editor is HSV sliders plus hex. | egui's pop-up picker can't signal drag end, which live preview needs. |
| 2026-10-11 | M3 | Sliders and handles preview live through an uncommitted "preview patch" on the session; releasing commits one undo step. | Smooth feedback without flooding the undo history. |
| 2026-10-11 | M3 | Dragging an edge handle on a fitted picture first sets the box to the visible picture and switches to stretch, then stretches that axis. Corner handles scale uniformly; Shift snaps rotation to 15°. | What you drag is what you see. |
| 2026-10-11 | M3 | Golden images (128×72) are generated on the software Vulkan renderer CI uses (`RW_GPU_FALLBACK=1 RW_UPDATE_GOLDEN=1`). Tolerance: ≤ 1 % of pixels may differ by more than 6 levels, and the average of any channel may shift by at most 0.75 levels. | A 25 % change to one colour formula shifts the average ~2.5 levels and is caught; GPU-to-GPU noise is far below. |
| 2026-10-11 | M10 (early, at the user's request) | Windows distribution: a per-user NSIS installer (no admin/UAC, Start menu + desktop shortcuts, Apps & Features uninstall) and a portable zip, built by `.github/workflows/release.yml` on version tags (draft release) or on demand. Static C runtime (no VC++ redistributable); FFmpeg LGPL DLLs ship beside the exe (replaceable, as LGPL requires); licence notices generated by cargo-about. CI self-tests both the portable folder and a silent install with FFmpeg removed from PATH. | The user asked for a one-click download with no install requirements. |
| 2026-10-11 | M10 | The app ranks every adapter that can draw to the window (discrete → integrated → virtual → software) so it opens on machines without a usable GPU (WARP on Windows). Release builds have no console window; startup failures show a message box pointing at the log folder. | Maximise the machines it runs on. |
| 2026-10-11 | M10 | Builds are unsigned for now; SmartScreen warns on first run. Signing is a matter of adding a certificate to the release workflow. | A code-signing certificate is a cost/identity decision for the owner. |
| 2026-10-11 | M10 | `brand-lint` exempts `packaging/windows/` and the release workflow, which must name Windows registry keys and system paths. | PLAN.md's Definition of done exempts OS-integration code. |
| 2026-10-11 | M10 | Windows ships our own FFmpeg 8.1 build (MSYS2 UCRT64, `scripts/ffmpeg/build-windows.sh`): every decoder/demuxer/parser kept; only the encoders and muxers the app writes; no avfilter/avdevice/network; dav1d, OpenH264, libvpx, LAME and Opus linked statically into the FFmpeg DLLs. The script fails if any DLL needs anything but Windows system DLLs and its siblings. | Cuts the download substantially without narrowing what can be imported; avfilter returns when GIF export needs it (M5). |
| 2026-10-11 | M10 | H.264 encoder order: VideoToolbox, Media Foundation, NVENC, QSV, AMF, then OpenH264, then MPEG-4. | PLAN.md's patent mitigation: prefer encoders whose licensing the OS or GPU vendor covers; OpenH264 remains for systems without them (e.g. Windows N editions). |
| 2026-10-12 | M4 | Transitions sit centred on the cut and don't change the timeline's length. Inside the window the outgoing clip keeps playing (or holds its last frame) and the incoming one starts early (or holds its first frame). Length is 0.1–3 s and at most twice the shorter clip; a transition is dropped automatically when its clips stop being back to back. | The usual consumer-editor behaviour; nothing else moves when a transition is added. |
| 2026-10-12 | M4 | Sound cuts hard at the cut under a transition; fades on either clip still apply. | Simplest predictable behaviour; crossfading audio is a separate, optional feature. |
| 2026-10-12 | M4 | A speed change keeps the clip's content, so its length changes and later clips on the track move with it. Freeze frame splits the clip at the playhead and inserts a 2 s held frame (silent), pushing later clips along. | Matches mainstream editors; nothing is lost from the clip. |
| 2026-10-12 | M4 | Pitch-preserving speed uses WSOLA (overlap-add of 43 ms windows aligned by correlation) written in Rust; without pitch preservation the sound is resampled. Reversed clips read their source backwards in 0.25 s blocks. | No avfilter (`atempo`/`rubberband`) in the trimmed FFmpeg; WSOLA is simple, real-time and good for speech and music at 0.1–16×. |
| 2026-10-12 | M4 | Slow zoom ("Ken Burns") is parameterised as zoom in/out plus where it drifts to (pan across/down), not two rectangles. | One intensity slider plus three values covers the common moves without a rectangle editor; start/end rectangles can come with the keyframe editor. |
| 2026-10-12 | M4 | The green-screen key colour is picked by clicking the preview, which shows the clip with keying paused while picking. | Picking from the already-keyed picture would sample transparency. |
| 2026-10-12 | M4 | Effect noise (grain, tape, glitch, shake) uses an integer hash seeded by frame, not `sin`-based noise. | Identical on every GPU, so golden frames match across Metal, WARP and lavapipe. |
| 2026-10-12 | M4 | UI elements keep their size when their text changes: number boxes have a fixed minimum width (`layout::VALUE_BOX_WIDTH`), and timecodes, counters and status text use `layout::steady_text` (every digit as wide as the widest, box sized for the longest expected text). | 2026-10-12 | M4 | A strip above the top track takes drops that should go on a new track; the library and clip menus also offer "Add on a new track" / "Move to a new track above". The strip is always drawn, so nothing shifts when a drag starts. | Making a layered track was only possible by dropping into the empty space above the tracks, which didn't exist. |
| 2026-10-12 | M5 | Text items live on their own text tracks (above the video tracks); text tracks hold only text. | Mainstream layout; keeps titles from being bumped by video edits. |
| 2026-10-12 | M5 | A text item's transform size scales its natural size (`[1, 1]` = as laid out at its font size); the font size is a share of the canvas height, outline/shadow/box sizes shares of the font size. | Titles look the same at any canvas or export size, and the on-canvas handles still just scale. |
| 2026-10-12 | M5 | 33 OFL font families are bundled (≈ 9 MB, embedded in the app): title fonts plus Noto Sans Arabic and Devanagari, tried first for those scripts. CJK and colour emoji come from system fonts (Windows and macOS include them; Linux needs `fonts-noto-cjk`/`fonts-noto-color-emoji`). | 2026-10-12 | M5 | Typewriter and word-by-word reveal letters within the finished layout, so the text doesn't shift as it types; countdown shows whole seconds left; credits roll from just below to just above the frame over the item. | Matches common title tools; stable layout. |
| 2026-10-12 | M5 | Export presets keep the canvas shape and set the short side (480/720/1080/2160); 4K needs a 4K canvas or "Allow upscaling". Quality maps to bit rate (×0.55 / ×1 / ×1.8 of ≈ 4 Mbit/s per megapixel at 30 fps, less for HEVC/VP9/AV1). | Simple, predictable sizes; no surprise upscaling. |
| 2026-10-12 | M5 | Codecs and encoders are offered only when an encoder actually opens on this computer (probed in the background when the dialog opens). | 2026-10-12 | M5 | GIFs are 480p (or the project's size if smaller), 10–25 fps (15 by default), at most 30 s, quantised per frame with NeuQuant in Rust (`gif` crate). | PLAN.md's GIF spec; FFmpeg's palette filters aren't in the trimmed build. |

| 2026-10-12 | M6 | Stickers and emoji are 454 curated OpenMoji 17 SVGs (faces, hands, celebration, animals and plants, food and drink, weather, symbols, music), CC BY-SA 4.0, unmodified, embedded at build time with an index for search; credited per file in `assets/ATTRIBUTION.md` and in About. | PLAN.md names OpenMoji; the full set (4,500 files, many skin-tone variants and flags) would be larger than useful. |
